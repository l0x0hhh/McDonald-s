# 麦门小厨房 · 在线模型配餐

React + TypeScript + Vite；保留红黄奶油玩具厨房、3D 按钮、厨师待机和弹簧动画。系统中文字体，不加载远程字体。

## 启动与验证

在 `G:\program\McDonald-s\frontend` 执行：

```powershell
npm.cmd ci
npm.cmd run dev
npm.cmd test
npm.cmd run build
```

前端 [127.0.0.1:5173](http://127.0.0.1:5173/)，后端仍在 [127.0.0.1:18000](http://127.0.0.1:18000/)。浏览器默认请求同源 `/api`，由 Vite 开发/预览代理到后端；本机和局域网访问均无需让浏览器直连 18000。`VITE_API_BASE_URL` 默认留空，只在独立部署 API 时设置；静态生产部署需由 Web 服务器转发 `/api`。Windows 使用 `npm.cmd` 避免 `npm.ps1` 执行策略问题。`start-dev.cmd --check` 只检查前端连通性；不使用 8000。

同一局域网访问时运行 `npm.cmd run dev -- --host 0.0.0.0`，再打开这台电脑的局域网 IP 与 5173 端口。后端继续只监听回环，不需要开放后端端口。

## 在线流程

- 启动直接读取门店；网络失败保留需求并提供重试。
- 人数、预算口径、不辣人数可编辑；聊天草稿跨轮传给后端。无饮料、饭量控件可编辑；聊天返回的口味、会员资格等扩展字段会完整提交，不静默删除。
- 服务端模型返回 1–3 张方案卡，保留推荐顺序和自定义标题。行价标明菜单参考，官方报价作为总额；缺失费用不显示零。
- 单个取餐方式时，“就选这份”直接请求创建待支付订单；多个方式先由用户选择，再提交。请求仅包含 `plan_id / quote_id / take_way_code / idempotency_key`。
- 同步全局锁防双击和跨卡重复；同一报价重试复用幂等键。`E_PRICE_CHANGED` 替换对应卡片，等待再次点击，以新报价生成新键。
- 只在当前页跳转服务端返回的官方 HTTPS 支付链接，exact hosts 与后端一致：`m.mcd.cn`、`mcp.mcd.cn`、`mcd.cn`；不接受子域泛匹配、HTTP、自定义端口或 URL 用户信息。
- 创建订单 90 秒超时，不自动重试；网络断开、无法解码或提交结果未知时锁住再次下单，提示到官方订单核实。页面重载仍保留“待核实”标记。
- 已知订单与独立支付批准上下文保存在会话存储。只有订单号、方案、门店、金额和官方链接全部匹配且未过期时才提供恢复；异常结果仅保留订单核实信息。焦点/页面返回和手动查询只调用订单 GET；查询通过订单身份、提交代际和最新查询序号校验，旧查询不覆盖新单、不清除其他提交的未知标记；只有官方状态响应才能显示已支付。跳转失败可继续使用同一链接，不重建订单。
- 配餐接口超时 90 秒，门店/聊天/订单查询 30 秒。需求和门店变化后忽略旧配餐与下单响应的自动导航。

生产代码不导入样例 JSON 或本地聊天模板，不设离线切换、模拟订单或错误样例回退。测试夹具及显式 API mocks 仅位于 `tests/`。

## 视觉与交互

正文和表单/按钮 16px，说明 14px，装饰最小 12px，价格 34px。次级深棕 `#755b43`，红主按钮使用深红渐变。卡片可自然增高；桌面左右面板共用网格导轨与行高，结果体可滚动，移动端自然重排。取餐方式/帮助/门店弹窗保留焦点限制、Escape 关闭与焦点恢复；减少动态效果实时生效。

## 本轮证据

`G:/program/McDonald-s/frontend/verification/llm-online-v13/` 保存基线、RED、GREEN 与 build 日志。本地测试均使用显式假上游，不调用真实创建或支付接口。正式页面只有用户明确点选才会发起创建。

## Key 设置

右上角“设置”填写 DeepSeek API Key 与麦当劳 MCP Key。模型固定 DeepSeek（deepseek-flash）。空输入保留原值，保存后即时生效并清除旧方案；保存期间与下单互斥。Key 只保存在服务端，不回显、不存浏览器。
